## 2. Findings, ranked by what they cost the deliverable

### F1 — BLOCKER. The default valuation projects five years off one year. *(fixable offline)*

`valuation_engine.py:705-711`. The five-year high-growth rate is set to **last year's FCF change**,
capped at 35% / floored at −5%, then faded. The base level is the single most recent annual FCF.
Both the level and the rate are one-year readings.

Stored 2026-08-01 base-case results:

| Ticker | Method | Fair value | Implied vs price | `g_high` source |
|---|---|---|---|---|
| KO | multi_stage_fcf_dcf | $24.76 | **−71.7%** | fcf_yoy 11.7% |
| CRM | multi_stage_fcf_dcf | $610.92 | **+232.0%** | fcf_yoy 15.8% |
| QCOM | multi_stage_fcf_dcf | $335.83 | **+127.5%** | fcf_yoy 14.9% |
| NVDA | multi_stage_fcf_dcf | $318.63 | +58.7% | fcf_yoy capped from 58.9% |
| JPM | excess_return_on_equity | $176.73 | −49.8% | n/a |
| PGR | excess_return_on_equity | $132.28 | −37.4% | n/a |
| CVX | cycle_normalized…placeholder | $150.40 | −23.6% | n/a |
| PLD | ffo_nav | $147.98 | +2.3% | n/a |

Dispersion −72% to +232% on eight large-cap names. KO's is compounded: the 2025 base FCF of $5.30B is
roughly half the prior run-rate, so a depressed base is grown at a depressed-year rate.

**This is not an arithmetic bug — the arithmetic was fixed.** It is that the anchor case is built on a
one-year delta while **five years of history already sit in state** (`annual_series`, VAL-10;
`fcf_history_n=5` on 6 of 8 tickers). The judgment layer can reach that history via
`base_fcf_method`; the default case cannot. That is why every memo has to argue against its own engine.

Also: `wacc` and `g_terminal` are sector constants (`SECTOR_WACC`). KO gets 9.0% / 2.5%. Even the
argued mid-cycle case only reaches $40.52 against ~$88.

**Offline-fixable and offline-verifiable.** Recompute all eight stored slices with a history-based
base and rate. Zero API calls.

### F2 — HIGH. The headline rating/target in the structured artifact can contradict the memo. *(fixable offline)*

`artifacts.py:412` — `_PRICE_TARGET_RE` matches `price target|PT|fair value|target price`. Because
memos discuss the engine's *fair value* in the recommendation section, the regex lifts the engine
number as the desk's price target:

- KO — `rating: HOLD`, `price_target: "$24.76"`. The memo issues no target and argues that number down.
- QCOM — `rating: HOLD`, `price_target: "$335.83"`. The memo explicitly **rejects** that figure.
- PGR — `rating: HOLD`, `price_target: "$132.28"`.

**Scope, checked:** this does *not* reach the .docx the graph exports — `export_docx.py` writes memo
prose and never reads these fields. It lives in `clean_memo.json` and on the deck cover
(`pdf_generator.py:1224-1225`), which is CLI-only and hand-run. The already-rendered
`QCOM_2026-07-30_presentation.pdf` cover reads **`Rating HOLD` / `Implied upside 121.5%`** — internally
contradictory on a client-facing page. So: latent in the shipped .docx path, live in the deck path.

`OUT-03` logged this as "null when phrasing differs." It is worse than null — it is confidently wrong.
Fix is the one already proposed there: have synthesis emit a machine-readable rating/target line
rather than loosening a regex.

### F3 — HIGH. Banks, insurers and REITs are asked about the wrong dials. *(design offline, validate live)*

Verified in code, still open from the 2026-08-02 review. `CRITIQUE_SYSTEM_PROMPT` (`agents.py:1263`)
is a single global prompt offering only `wacc | g_high | g_terminal | high_growth_years | fade_years |
base_fcf_method`. It is sent for **every** archetype. The engine then silently reinterprets
(`valuation_engine.py:1683-1691`):

```
wacc   → cost_of_equity
g_high → plowback   (via growth / roe)
```

Comment calls this "compatibility for the committed 2026-07-30 critiques." It is not legacy — it is
the only path on every live run. JPM's `wacc [0.09, 0.105]` was *reasoned about* as a DCF discount
rate and *consumed* as cost of equity. Two consequences: the reasoning shown to a reader is about a
different quantity than the number computed; and C2 (every argued input cites resolvable evidence)
passes while the evidence was written about something else. `ARGUED_INPUT_BOUNDS` already has the
native dials — nothing proposes them.

Prompt + bounds work is offline. Proving it changed behaviour needs a live run.

### F4 — HIGH. The whole forward-estimate epic is dark code.

`forecast_engine.py` (20k) is imported by **nothing** outside its own tests. No graph node, no state
writer, no artifact reader. `historical_profile`, `forecast`, `driver_critique`, `dcf_modelled`,
`consensus_reconciliation` are declared in `state.py` and read only by the grader — which scores them
`vacuous` because they are always empty. FWD-08/09/10/11 all TODO.

Worse, the driver templates say the data is not there yet. Across all 16 archetypes:

| Basis status | Meaning | Archetypes affected |
|---|---|---|
| `profile` (usable now) | history is computed today | general, asset_light, asset_heavy, asset_heavy_industrial, pre_profit_growth — **5 fully clean** |
| `derivable` | filing lines parse, no ratio computed yet | bank_lender (5/5), insurance (3/3), mortgage_reit (3/3) |
| `unavailable` | **no filing history exists at any depth** | cyclical_commodity (3/3), equity_reit (3/4), reit_real_estate (3/4), telecom (2/3), utility (2/3), midstream (2/3) |

`cyclical_commodity` — the archetype CVX was swapped in to unblock — has **zero** grounded drivers.
The template's own rule is that ungrounded drivers must be refused, not defaulted. So the epic can
run today only on plain FCF names, and the exact names that motivated it (JPM, PGR, PLD, CVX) are the
ones with nothing to stand on. `forecast_engine.py` also does not call `drivers_for()` at all
(FWD-11), so even the clean archetypes hardcode driver names.

## 3. Recommendation given zero API credit

Order is by *what can be finished and proven today*, not by severity alone.

**Do now (free, and provable on the eight stored slices):**

1. **F1 — history-based default case.** Base FCF from the existing 5-year `annual_series` rather than
   the last print; growth from a multi-year trend rather than one YoY delta; make sector WACC
   overridable by a company-specific input. Recompute all eight stored slices offline and put the old
   and new fair values side by side. If KO stops printing $24.76 and CRM stops printing $611, the
   single largest credibility gap in the system closes, with no LLM call.
2. **F2 — kill the price-target regex.** Have synthesis emit an explicit machine-readable
   rating/target line; make the field `null` rather than guessing when it is absent. Trivial, and it
   removes the one place a client-facing page can contradict the memo.
3. **F6 — mock-LLM harness.** Canned responses per node so the full graph runs offline. This is the
   enabler: it converts "no credit" from a blocker into a non-issue for everything except final
   validation, and it is the only way to test F3, F4 and F5 before spending.

**Design now, validate when credit returns:**

4. **F3 — archetype-aware critique prompt** + extend `ARGUED_INPUT_BOUNDS`, then **delete** the
   `wacc → cost_of_equity` / `g_high → plowback` shim rather than extend it. Writable today; only a
   live run proves the model actually argues the new dials.
5. **F5 — schema 1.2 + judgment bars on the football field.** Also free, also verifiable against
   stored slices.

**Decide before more building:**

6. **F4 — scope Epic F to what the data supports.** Ten of sixteen archetypes have drivers with no
   computable history. Either (a) restrict the forecast path to the five clean archetypes and refuse
   the rest loudly, or (b) fund the extraction work for the `derivable` set (banks, insurers,
   mortgage REITs — the ratios are computable from lines that already parse) and accept that
   `unavailable` drivers (occupancy, subscribers, throughput, realised price) need a data source this
   system does not have. Building more forecast machinery before this call is spend on code that
   cannot run.

mark Grok's baseline table as pre-fix.
